# باقات الرياض

واجهة عربية للبحث عن باقات المطاعم ومقارنتها. بيانات الباقات تُدخل من لوحة التاجر المعتمد، وتعرض تفاصيل الباقة موقع الفرع حسب الإحداثيات المسجلة. البحث يعرض أول ١٠٠ نتيجة مرتبة بالسعر النهائي.

## التشغيل

1. أنشئ مشروع Supabase مستقلًا لباقات وطبّق ملف `supabase/migrations/202611240001_baqat.sql` مرة واحدة.
2. فعّل تسجيل البريد وكلمة المرور وتأكيد البريد. اضبط عنوان التطبيق ضمن عناوين إعادة التوجيه المسموحة. بعد تأكيد البريد، يعود المستخدم للواجهة لتسجيل الدخول.
3. أضف رابط المشروع ومفتاحه العام القابل للنشر إلى `dist/config.js`. يُستخدم معرّف المشروع والمفتاح العام في المتصفح. أبقِ مفاتيح الإدارة وكلمات المرور خارج المصدر.
4. شغّل الواجهة محليًا بالأمر `python3 -m http.server 8080 --directory dist` أو انشر مجلد `dist` في استضافة ثابتة.
5. يسجل التاجر حسابًا ويقدم طلب اعتماد من «حسابي». راجع المنشأة، ثم اعتمد معرف المستخدم المؤكد من حساب الإدارة في قاعدة البيانات.

```sql
update public.baqat_merchants
set approved = true
where user_id = '<معرف المستخدم المؤكد>';
```

6. يسجل التاجر عنوان الفرع وإحداثياته وسعر الباقة الكامل وسعتها وفترة توفرها بتوقيت الرياض. يحفظها كمسودة ثم ينشرها بعد التحقق من البيانات.

## الرموز

يتطلب الإصدار حساب عميل مسجلًا وباقة منشورة متاحة في الوقت الحالي. يحفظ الخادم بصمة الرمز فقط، ويقصر الاستخدام على التاجر صاحب الباقة. الرمز صالح حتى ٣٠ دقيقة أو نهاية العرض، أيهما أسبق. كل رمز يقبل استخدامًا واحدًا. يحد الخادم الإصدار إلى عشرة رموز لكل حساب في الساعة، وإلى رمز نشط واحد لكل باقة في الوقت ذاته. تبقى الجلسة والرمز الصريح في ذاكرة الصفحة الحالية.

## التحقق قبل الإطلاق

جرّب إنشاء حسابين منفصلين للعميل والتاجر وحسابًا ثالثًا لاختبار العزل. تحقق من ظهور باقة حقيقية بعد نشرها، ومن موقع الفرع، وإصدار الرمز، ورفض استخدامه من حساب تاجر آخر، وقبوله مرة واحدة من التاجر صاحب الباقة. لا تُباع الباقة أو يُحصّل ثمنها داخل التطبيق.
